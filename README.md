# AgriCarbon Match AI

เดโมเว็บภาษาไทยแบบ mobile-first สำหรับเกษตรกรและผู้ประสานงาน ใช้หน้าเดียวกันทั้งบนเบราว์เซอร์และใน LINE LIFF มี 2 ส่วน

1. **ค้นหาโรงงาน (F3):** เลือกวัสดุ ปริมาณ (ตัน) และจังหวัด แล้วดูโรงงานที่รับวัสดุนั้นภายใน 80 กม. เรียงตามราคาจำลอง
2. **วางแผนล็อตฟางข้าว:** ผู้ประสานงานบันทึกออเดอร์จากโรงงาน ระบบเสนอชุดแปลงและคิวด้วยกติกาฝั่งเซิร์ฟเวอร์ ผู้ประสานงานปรับชุดแปลง บันทึกการยืนยันของแต่ละฝ่าย บันทึกน้ำหนักชั่งจริง และปิดล็อต

เว็บเดโมใช้กติกาฝั่งเซิร์ฟเวอร์ (Python) และข้อมูลจำลองเท่านั้น ไม่ต้องใช้ AWS credentials

## รันบนเครื่อง

ต้องใช้ Python 3.12 ขึ้นไป เว็บเซิร์ฟเวอร์ใช้เฉพาะ Python standard library ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```sh
python3 webapp.py
```

เมื่อเริ่มสำเร็จ เซิร์ฟเวอร์พิมพ์ `http://127.0.0.1:8000` ให้เปิด URL นี้ในเบราว์เซอร์ (ผูกกับ 127.0.0.1 เท่านั้น เปิดจากเครื่องอื่นไม่ได้) ถ้าพอร์ต 8000 ถูกใช้อยู่ ให้ตั้งตัวแปร `PORT` เช่น `PORT=8001 python3 webapp.py` แล้วเปิดพอร์ตนั้นแทน

### หน้าเว็บที่ควรเห็นเมื่อไม่ตั้ง `LIFF_ID`

- หน้าโหลดและใช้งานได้ตามปกติในเบราว์เซอร์ทั่วไป ไม่มีการโหลด LIFF SDK และไม่มีข้อความ «เชื่อมต่อ LINE ไม่สำเร็จ»
- มีแท็บ «ค้นหาโรงงาน» และ «วางแผนล็อต»
- ลองค้นหา ฟางข้าว 2 ตัน จังหวัดนครสวรรค์ ควรเห็นโรงงาน B ที่ 80 กม. ราคาจำลอง 1,100 บาท/ตัน ก่อนโรงงาน A ที่ 35 กม. ราคาจำลอง 950 บาท/ตัน
- ในแท็บ «วางแผนล็อต» ฟอร์มออเดอร์มีปุ่มตั้งค่า 10 ตัน
- ถ้าหน้าไม่ขึ้น หรือเห็น «โหลดผลไม่ได้» พร้อมปุ่มลองใหม่ ให้ตรวจว่าเซิร์ฟเวอร์ยังรันอยู่และพอร์ตตรงกับ URL

## ขอบเขตและข้อสมมติ

เดโมนี้ไม่มี: การส่งข้อความ LINE จริง การจ่ายเงิน การซื้อขายหรืออ้างสิทธิ์คาร์บอนเครดิต และการยืนยันตัวตนผู้ใช้จริง

- ผู้ประสานงานบันทึกการยืนยันของโรงงาน เกษตรกร และผู้รับจ้างด้วยมือ (หน้าเว็บแสดง «บันทึกโดยผู้ประสานงาน») ระบบไม่ส่งข้อความถึงใคร
- สถานะเก็บในหน่วยความจำของเซิร์ฟเวอร์แยกตาม session (cookie) อยู่ข้ามการรีเฟรชหน้า แต่**หายเมื่อรีสตาร์ตเซิร์ฟเวอร์** และ session ที่ไม่มีการใช้งาน 24 ชั่วโมงจะหมดอายุ
- ชื่อบุคคลและโรงงานเป็นข้อมูลสมมติ
- ตัวเลขทั้งหมดเป็นข้อสมมติของเดโม ไม่ใช่ข้อมูลจากโรงงานหรือผู้รับจ้างจริง ต้องตรวจในช่วงนำร่อง:
  - ราคาฟางที่จ่ายเกษตรกร 300 บาท/ตัน ค่าอัดฟ่อน 250 บาท/ตัน ค่าขนส่ง 5 บาท/ตัน/กม. (ต้นทุนส่งถึงโรงงานเป็น «ประมาณการ» และแสดงแยกจาก «ราคาที่โรงงานเสนอ»)
  - คิวรถอัดฟ่อนและรถขนจำลอง ความจุ 15 ตัน/วัน
  - ความชื้นสูงสุดตั้งต้น 20% ชุดแปลงที่เสนอมีปริมาณประมาณการไม่น้อยกว่า 120% ของเป้าหมาย
  - ระยะทางจากแปลงถึงโรงงานเป็นค่าจำลอง ไม่ได้คำนวณจากพิกัดจริง เพดานขนส่ง 80 กม.
- เดโมไม่แสดงกำไรหรือรายได้ของเกษตรกร และไม่ยืนยันสมมติฐานการประหยัดต้นทุนหรือการเข้าร่วมของผู้ซื้อ

## Deploy แบบ HTTPS และเปิดใน LINE

LIFF ต้องใช้ URL แบบ HTTPS ตัวอย่างวิธีเดียว: รัน WSGI app บนผู้ให้บริการที่รัน Python และให้ HTTPS ที่โดเมนของโฮสต์ (เช่น PaaS ที่ออกใบรับรองให้) ชื่อบริการและหน้าจอตั้งค่าต่างกันตามผู้ให้บริการ ให้ปรับตามผู้ให้บริการที่ทีมเลือก

1. ส่งซอร์สขึ้นโฮสต์ ต้องรวมโฟลเดอร์ `web/` และไฟล์ Python ในรากโปรเจกต์ (`webapp.py`, `matching.py`, `lot_*.py`)
2. ติดตั้ง gunicorn บนโฮสต์เท่านั้น (ไม่จำเป็นสำหรับรันบนเครื่อง): `python -m pip install gunicorn`
3. ตั้ง start command:

   ```sh
   gunicorn --workers 1 --threads 4 --bind "0.0.0.0:${PORT:-8000}" webapp:application
   ```

   ต้องใช้ worker เดียว (`--workers 1`) เพราะสถานะ session เก็บในหน่วยความจำของโปรเซส ถ้ามีหลาย worker แต่ละตัวจะมีสถานะของตัวเอง และผู้ใช้จะเห็นข้อมูลหายหรือขึ้น session ใหม่สลับกัน ใช้ `--threads` เพื่อรองรับคำขอพร้อมกัน
4. ตั้งตัวแปร `LIFF_ID` ในส่วน environment variables ของบริการที่รันเว็บ (ต้องมีค่าก่อนเปิดใน LINE) แล้วรีสตาร์ตบริการ เซิร์ฟเวอร์อ่านค่านี้จาก `GET /api/config` และ `GET /api/demo` แล้วหน้าเว็บจึงเริ่ม LIFF
5. เปิด URL HTTPS ของโฮสต์ในเบราว์เซอร์ แล้วลองค้นหาตามตัวอย่างด้านบน
6. ตั้ง Endpoint URL ใน [LINE Developers Console](https://developers.line.biz/console/):
   1. เลือก Provider และ LINE Login channel ของทีม
   2. เปิดแท็บ LIFF แล้วเพิ่ม LIFF app (หรือเปิดอันที่มี)
   3. ตั้ง **Endpoint URL** เป็น URL รากแบบ HTTPS ของเว็บที่ deploy เช่น `https://your-domain.example/` ค่านี้**ต้องขึ้นต้นด้วย `https://`**
   4. คัดลอก LIFF ID ที่ Console ออกให้ไปใช้เป็นค่า `LIFF_ID` ในขั้นตอนที่ 4
7. เปิดลิงก์ LIFF จากแอป LINE และลองค้นหาด้วยข้อมูลตัวอย่าง

README นี้เป็นขั้นตอนที่ควรทำ ยังไม่ได้ยืนยันว่า deploy จริงหรือเปิดใน LINE สำเร็จ ดูผลที่ตรวจจริงใน `docs/test-report.md` เมื่อมี

## CLI agent (แยกจากเว็บเดโม)

CLI agent เป็นส่วนแยกจากเว็บเดโม รันด้วย `uv run agent.py` ใช้ Strands และต้องมีสิทธิ์เข้าถึง Amazon Bedrock ใน region ap-southeast-1 เว็บเดโมไม่เรียก agent นี้และไม่ต้องใช้ AWS
